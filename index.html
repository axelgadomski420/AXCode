AXCode to deklaratywny język aplikacji. Jeden plik .ax opisuje interfejs, stan, dane, nawigację, bezpieczeństwo, dostępność, offline i testy. Dowód działania

AXBridge nie jest mockupem. To działająca beta.

AXBridge powstał jako pierwsza pełna aplikacja w AXCode. Nie demonstruje tylko składni — pokazuje, że jeden język może obsłużyć realny produkt: konta, wiadomości, media, AI, offline, bezpieczeństwo, dostępność i tryb alarmowy.

🔐

E2EE

Wiadomości są szyfrowane na urządzeniu. Serwer przekazuje ciphertext i minimalne metadane, nie plaintext.

📡

Offline-first

Kolejka outbox, idempotentne identyfikatory, ponawianie z exponential backoff i wznowienie po powrocie sieci.

🎧

Wielokanałowość

Tekst, mowa, kod Morse’a, język migowy, muzyka, obraz, wideo i alarm są jednym modelem wiadomości.

Persona-aware

Onboarding dostosowuje kanały wejścia i wyjścia dla osób głuchych, niewidomych, głuchoniewidomych oraz z ograniczoną sprawnością ruchową.

Filozofia

Aplikacja powinna być czytelna jak specyfikacja produktu.

AXCode nie próbuje zastąpić wszystkich języków programowania. Jest językiem warstwy aplikacji: ekranów, stanu, danych, nawigacji, uprawnień, dostępności i testów. Kod natywny pozostaje dostępny przez bridge, ale nie jest wymagany do zbudowania typowego produktu.

📄

Jeden ekran = jeden blok

Ekran zawiera własny stan, layout, zdarzenia, nawigację i efekty. Nie trzeba skakać między plikiem widoku, plikiem stylów, plikiem stanu i plikiem logiki.

⚡

Reaktywność bez glue code’u

Zmiana stanu automatycznie aktualizuje UI. Programista nie pisze ręcznej synchronizacji DOM, listenerów ani cyklu życia komponentu.

🧠

Błędy po ludzku

Kompilator pokazuje problem, przyczynę, pozycję i proponowaną poprawkę — po polsku i angielsku. Błąd ma uczyć, a nie tylko przerywać build.

♿

Dostępność jako typ

Brak etykiety pola, obrazu bez opisu, zbyt mały cel dotykowy albo zły kontrast są wykrywane przed uruchomieniem aplikacji.

🔒

Bezpieczeństwo w modelu danych

Klucze, tokeny i dane wrażliwe mają jawną klasę przechowywania. Nie można przypadkiem zapisać sekretu w niezabezpieczonym store.

🚫

Mniejsza powierzchnia języka

Brak dowolnych makr, dynamicznej ewaluacji, globalnych selektorów CSS i pięciu składni na ten sam problem. Mniej możliwości oznacza mniej błędów.

Składnia

Kod, który można przeczytać bez znajomości frameworka.

Poniższy fragment odwzorowuje realny wzorzec z AXBridge: profil dostępności, lokalny store, ekran czatu, wybór kanału komunikacji i potwierdzenie wyniku AI przed wysłaniem.

axbridge.ax 
enum Channel
  text
  speech
  morse
  sign
  music

data AccessibilityProfile
  preferredInput Channel
  preferredOutput Channel
  morseWpm Number
  vibrationStrength Number
  textScale Number
  highContrast Boolean
  reduceMotion Boolean
  confirmBeforeSend Boolean
  showConfidence Boolean

store profile local
  single AccessibilityProfile
  key "axbridge.profile"

screen Chat
  title "Rozmowa"

  state draft Text = ""
  state inputMode Channel = profile.preferredInput
  state selectedCandidate Text = ""
  state signConfidence Number = 0

  column
    list messages
      item message
        messageBubble(message)

    if inputMode is Channel.sign
      cameraPreview
        accessibility label "Kamera rozpoznawania języka migowego"

      card
        text "Rozpoznane znaki"
          style heading

        text "Pewność: " + round(signConfidence * 100) + "%"

        button "Akceptuj i wyślij"
          style buttonPrimary
          when tapped
            // AI proponuje. Człowiek potwierdza.
            sendSign(selectedCandidate, signConfidence)

    if inputMode is Channel.morse
      row
        button "•"
          accessibility label "Kropka"
          when tapped
            append "." to morseBuffer
            vibrate short

        button "—"
          accessibility label "Kreska"
          when tapped
            append "-" to morseBuffer
            vibrate medium
Benchmark

Ile naprawdę można zaoszczędzić?

Poniższe liczby dotyczą referencyjnej aplikacji: logowanie, lista, dodawanie, usuwanie, tryb ciemny, zapis lokalny i responsywny layout. To nie jest marketingowe „zawsze 10× mniej”, lecz uczciwy model redukcji boilerplate’u.

🌐

HTML + CSS + JavaScript

Osobne warstwy struktury, wyglądu i logiki. Programista ręcznie aktualizuje DOM, obsługuje zdarzenia, serializuje stan i dba o dostępność.

Orientacyjnie 220–320 linii

📱

React Native

Jeden język aplikacji, ale zwykle osobne pliki komponentów, stylów, nawigacji, stanu i warstwy danych. Mocny ekosystem, jednak więcej konfiguracji i abstrakcji.

Orientacyjnie 260–420 linii

🅰️

AXCode

Jeden plik `.ax` opisuje UI, stan, dane, dostępność, motyw i zapis lokalny. Kompilator generuje warstwy platformowe i eliminuje powtarzalny kod.

Jak bronić tych liczb przed recenzentami

  • Redukcja linii nie jest celem samym w sobie. Celem jest redukcja przypadków zmiany, duplikacji i błędów integracji między warstwami.
  • AXCode eliminuje trzy źródła boilerplate’u: ręczną synchronizację UI ze stanem, powtarzalną konfigurację dostępności oraz glue code między danymi, widokiem i nawigacją.
  • Kompilator przenosi błędy z runtime’u do czasu kompilacji. Nieznany ekran, zły typ pola, brak etykiety dostępności albo zapis sekretu w niezabezpieczonym store są wykrywane wcześniej.
  • Nie ma darmowej abstrakcji. AXCode zmniejsza kod aplikacji, ale zwiększa złożoność kompilatora i runtime’u. To świadomy trade-off: złożoność przenosimy z milionów aplikacji do jednego narzędzia.
  • AXBridge jest dowodem empirycznym. Nie musimy wierzyć w model redukcji — możemy porównać działającą aplikację referencyjną z równoważną implementacją w HTML/CSS/JS i React Native.
Kompilator

Jeden front-end. Wiele backendów.

AXCode nie tłumaczy tekstu bezpośrednio na Swift, Kotlin czy JavaScript. Najpierw tworzy neutralną reprezentację aplikacji AXIR, a dopiero potem generuje kod dla platformy.

app.ax │ ▼ Lexer ──► Tokeny, pozycje, komentarze │ ▼ Parser ──► AST + recovery + wiele błędów naraz │ ▼ Type Checker ──► typy, zasięgi, stany, uprawnienia, dostępność │ ▼ AXIR ──► platformowo-neutralny graf aplikacji │ ├──► Optimizer │ • dead code elimination │ • inline komponentów │ • memoizacja stabilnych fragmentów │ • tree shaking │ ├──► iOS Backend ──► Swift + SwiftUI / native runtime ├──► Android Backend ──► Kotlin + Jetpack Compose / native runtime ├──► Web Backend ──► Wasm core + TypeScript glue + DOM renderer ├──► Desktop Backend ──► natywne shelle │ └──► Dev Server • hot reload • live preview • accessibility inspector • device simulator

Hot reload

Zmiana pliku `.ax` tworzy patch AXIR. Runtime stosuje zmianę bez utraty stanu, jeśli typy i struktura danych są zgodne. Przy zmianie niekompatybilnej wykonuje bezpieczny restart ekranu.

Diagnostyka

Każdy błąd ma identyfikator, lokalizację, wyjaśnienie w PL/EN oraz sugerowaną poprawkę. Parser nie zatrzymuje się na pierwszym błędzie — pokazuje wiele problemów jednocześnie.

Web i WebAssembly

Logika aplikacji może być kompilowana do WebAssembly, a cienka warstwa TypeScript obsługuje zdarzenia, nawigację i integrację z przeglądarką. Renderer DOM zapewnia dostępność i SEO.

Podgląd na żywo

Dev server pokazuje ten sam ekran jako iPhone, Android, tablet i desktop, z możliwością symulacji trybu ciemnego, dużego tekstu, redukcji ruchu i czytnika ekranu.

AXBridge 1.5.1

Aplikacja referencyjna AXCode.

AXBridge to nie demo składni. To kompletny produkt dostępnościowy, który dowodzi, że AXCode wystarcza do zbudowania aplikacji z kontami, mediami, AI, offline, bezpieczeństwem i trybem alarmowym.

Komunikacja

Rozmowy 1:1 i grupowe, wiadomości tekstowe, głosowe, obrazowe, wideo, pliki audio, odpowiedzi, statusy dostarczenia i kolejka offline.

Dostępność

Onboarding persona-aware, Morse, mowa, język migowy, alerty dźwiękowe, wibracje, tryb uproszczony, hardware switch i czytniki ekranu.

Bezpieczeństwo

E2EE, safety numbers, weryfikacja QR, zaszyfrowane media, zaszyfrowane klucze, recovery codes i ochrona przed atakiem MITM.

AI

Bring Your Own AI: użytkownik wybiera dostawcę LLM, tłumacza, STT, TTS lub generatora muzyki. Klucze API są szyfrowane lokalnie.

AXBridge — warstwa produkcyjna 
// Kolejka offline przetrwa restart aplikacji
store outbox local encrypted
  list OutboxItem
  key "axbridge.outbox.v6"

function enqueueOutbox(
  conversationId Text,
  kind Text,
  plaintext Text,
  mediaRef Text?
)
  set ciphertext = encryptForPeer(peerId, plaintext)

  add OutboxItem(
    id = newId(),
    idempotencyKey = newId(),
    conversationId = conversationId,
    kind = kind,
    ciphertext = ciphertext,
    mediaRef = mediaRef,
    attempts = 0,
    status = "pending"
  ) to outbox

  save outbox
  kickQueue()

when isOnline changes to true
  flushQueueOnReconnect()

Specyfikacja

Pełna specyfikacja języka AXCode

Poniższa specyfikacja opisuje minimalny, spójny core języka. Rozszerzenia platformowe są opcjonalne i nie psują przenośności podstawowego kodu.

1. Jednostki programu

Podstawowymi jednostkami są app, screen, component, data, enum, store, theme, api i test.

2. Typy

Wbudowane typy: Text, Number, Boolean, Date, List<T>, Json, File oraz typy opcjonalne T?.

3. Stan

state jest lokalny dla ekranu, global state dla aplikacji, a store jest trwały. Store może być local, synced lub encrypted.

4. Zdarzenia

Zdarzenia mają formę when tapped, when changed, when screen appears, when valid, when error i when app launches.

5. Listy

Listy UI są deklaratywne: list, item i empty. Nie ma ręcznego renderowania ani kluczy DOM w podstawowym przypadku.

6. Formularze

Formularz posiada walidację deklaratywną: required, min length, max length, type email, type password oraz komunikaty błędów.

7. Nawigacja

Nawigacja jest typowana: go to ScreenName, go back oraz przekazywanie parametrów ekranu. Kompilator wykrywa nieistniejące ekrany i złe typy parametrów.

8. Motywy

Motyw definiuje kolory, promienie, cienie, typografię i tryb jasny/ciemny. Może następować za ustawieniami systemu lub być wymuszony przez aplikację.

9. Animacje

Animacje są ograniczone do przewidywalnych przejść: appear, press, transition i layout. Są automatycznie wyłączane przy reduce motion.

10. API i dane

api opisuje endpointy, metody, typy odpowiedzi i obsługę błędów. store obsługuje offline-first, szyfrowanie i synchronizację.

11. Uprawnienia

Kamera, mikrofon, lokalizacja, powiadomienia i dane biometryczne mają jawny model zgód. Zgoda jest odwoływalna i audytowalna.

12. Testy

Testy jednostkowe, integracyjne, UI i dostępności są częścią języka. Test może opisywać stan początkowy, akcję użytkownika i oczekiwany wynik.

Dla recenzentów

Dlaczego to jest wykonalne.

AXCode nie wymaga wynalezienia nowej fizyki. Składa się z dobrze znanych, sprawdzalnych elementów: parsera, systemu typów, IR, generatorów kodu i runtime’u UI.

Teza 1

Redukcja kodu wynika nie z „magii”, lecz z eliminacji trzech powtarzalnych warstw: synchronizacji UI, konfiguracji dostępności i glue code’u danych.

Teza 2

Jeden język aplikacji może kompilować się do wielu platform, jeśli pośrednią reprezentacją jest semantyczny graf UI, a nie konkretny framework.

Teza 3

Jakość języka mierzy się nie liczbą funkcji, lecz liczbą błędów, których nie da się łatwo popełnić. AXCode ogranicza powierzchnię języka świadomie.
